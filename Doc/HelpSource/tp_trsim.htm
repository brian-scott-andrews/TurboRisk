TRSim

Overview

TRSim is a simulation environment where the TRP programmer can test his/her own TRP against other TRPs. Basically, TRSim can autonomously run many TurboRisk games using different sets of player (configured by the user), and provides some tools to analyse the results of those games.

TRSim can also be used to rank a group of TRPs for their relative strength under a given set of rules.

TRP bot strategies

The source headers of many TRP bots describe their intended strategies. These descriptions are heuristic summaries, not guarantees of behavior. The TRP Bot Strategies topic summarizes the AI-assisted bots authored by Brian S. Andrews, including Grudge.

Running a simulation

Select the Simulation tab and specify the following parameters:

  • The number of games to play. TRSim reads the rules from the main TurboRisk configuration file.
  • The number of players per game. This number is a range, so as inside the same simulation you can have games with different number of players (from 2 to 10).
  • Three lists of players: always included (will play all the games), randomnly included (may play some of the games) and never included (will play no game). You can drag and drop names from one list to the other.
  • A map file: the simulation can run either with a visible map or not.
  • Stats window: the simulation can run either with a visible stats window or not.
  • TRP error handling: tell TRSim what to do when a TRP generates an error.
  • Log files. Every simulation produces two log files: game and cpu usage. The first one is a text file containing information about the played games, while the second is an ini-like file format containing some info about the execution of the TRPs. Everytime you run a simulation, the new data are appended to the log files, so you can use always the same log files. However, you can also use different log files, for example for different set of rules or different simulation configurations.
  • Game limits: the duration of each game can be limited, in number of turns, number of seconds, or both. 0 in one of these parameters means "no limit".

Analysing the results

Select the Analysis tab, specify the file you want to analyse, and click the corresponding button.

You can open multiple log files of each kind, just leaving the first window open, changing the log file name and clicking the button again. This is intended to make comparing results from different simulations easier.

Game log

For each simulated game, the game log file contains the following information (Games tab):
  • Date and time it was played.
  • Termination type (completed, trp error, time limit, turn limit, aborted by user...)
  • Duration, in term of time and turns
  • last turn played by each player
  • number of remaining armies the winner had when the game finished
  • for unfinished games, the number of armies and territories each player had when the game was interrupted

The Summary tab is similar to the Ranking tab of the History window, with few more columns:

  • average rank of each player
  • average number of turns per game
  • average number of turns per won games
  • average number of armies remaining after having won a game (only completed games are taken into account)

The Player's analysis tab compare a player to all its competitors. The game accounted are only the completed ones, which contained the chosen player and its competitor. For each competitor, you can see:

  • in how many games the two players had to fight together
  • in how many games the competitor ranked better than the chosen player
  • in how many games the competitor ranked worse than the chosen player
  • same data in %
  • average rank difference between the two (only related to games where both participated)

CPU log

For each player TRSim monitors the number of phases (attack, placement, occupation...), the number of calls (each attack or placement phase may conatins many calls to the TRP code) and the total time used (milliseconds).

The main grid shows the average Time/Phase of each player and each phase, while the detail grid below shows all the data for any selected player.

Some important notes about CPU times:

  • they obviously depend on the performances of the PC
  • they can be affected by other programs running on the machine at the same time
