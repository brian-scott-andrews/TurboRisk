Running a TRP

Use the  TRP  menu or toolbar to compile the source and test an individual routine.

Compile

The compilation is a process where your source code is checked for possible syntax errors and - if there aren't - is converted into a more compact form suitable to be used by the TurboRisk script interpreter.

Compilation checks the source and verifies that the required TurboRisk procedures are present with compatible declarations. TurboRisk also compiles TRPs when they are loaded into a game.

Run

Choose  TRP > Run selected routine...  to test a procedure or function from the current source.

TRComp asks for a game context, then prompts for the selected routine's parameters. After execution, the results pane shows modified var parameters, a function result, and captured UMessage, ULog, UDialog and snapshot requests.

Testing a routine is not a full game simulation and does not write snapshot files.

Execution context

TRComp creates an editable test context for each run. Set up the game details your routine reads, including players, territory owners and armies, turn information, card rules, and player buffers. The context can be incomplete; it is the user's responsibility to make it consistent with the routine being tested.

Each routine test runs in an isolated game context. Game, territory, player, turn-order, random-number and script-runtime state is restored afterwards. The edited test context (including player buffers) and routine results are returned to TRComp.

TRComp provides context values directly; it does not load a TRD error snapshot or TRS saved game in this workflow. For repeatable tests, use the same context and parameter values.

Results and logging

The results pane shows the routine's return value and changed parameters. Utility calls such as ULog and UMessage are captured instead of being handled as they would be in a full game. These outputs help debug a routine but do not reproduce every game lifecycle event.
