Running a TRP

The  TRP  menu of TRComp gives you the options to compile and run the source code in the editing area.

Compile

The compilation is a process where your source code is checked for possible syntax errors and - if there aren't - is converted into a more compact form suitable to be used by the TurboRisk script interpreter.

You are not required to explicitly compile your TRP, because this is done by TurboRisk after the TRP has been loaded, and it's done by TRComp itself when you select  TRP > Run . Compilation is mostly useful to check the code for syntax errors without having to run the code itself.

Run

This function allows you to test your code. A TRP is essentially a collection of procedures and functions, and TRComp provides a quick and simple way to individually call each of them passing the proper parameters.

When you select  TRP > Run , TRComp shows a window containing a list of all the declared procedures and functions. Select the one you want to run, fill in the parameters table and click the  Run  button.

When the called procedure returns, the parameters table will show the value of any var parameter modified by your code.

Execution context

To test your code, you also need to simulate the tipical situations of a TurboRisk game. TRComp allows this through its Execution Context window, which you can open using the  TRP > Contex window  menu item. The same window gets automatically opened also anytime you select  TRP > Run , because there's no reason to run part of a TRP code without the proper execution context.

The  TRP > Load snapshot  menu option provides the possibility to load the execution context from a snapshot file (extension "TRD"), generated by a TRP error, or from a saved game (extension "TRS").

The Execution Context window contains four tabs:

  • Players: a list of the players involved in the game. For each player you can specify name, program name, color, nr of cards in hand, card turn in value, new armies to place. In the same tab you also define the number of the current player (your TRP).
  • Map: load the map to use in defining which territories are owned, and by which player. There are two ways to assign territories: if you left-click on a territory, it will be assigned to the player selected in the Quick assign combo box; if you right click, TRComp will show an Assign window. You can also generate a random territory assignement, where the players are chosen among the active players and the armies in each territory range from 1 to Max Armies.
  • Buffers: in this tab you can view or modify the buffers that your TRP can get or set through the UBufferGet and UBufferSet API functions.
  • Message: if you load a snapshot file, here you find the error message contained in it.

In creating an execution context, you have no particular constraint. You are not required to provide any of the information, but the making of a consistent contex for the code you want to test is up to you.

For example, if some of the territories are unassigned, there's no reason to call the Fortification procedure, but you're not prevented from doing that. Similarely, it's up to you to type in the program names or not, depending on if your code uses the PName() API function.

Generally speaking, make sure you provide the context information your program requires to run in a proper way.

Log

TRComp provides a Log window similar to the one you can activate in TurboRisk. It's particularely useful to test and debug your code if used in combination with the ULog() API function.
