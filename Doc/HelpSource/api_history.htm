Public action history

function HCount: integer;
function HGet(Index, Field: integer): integer;

HCount returns the number of recorded public actions in the current game. HGet reads one field of action Index, numbered from 1 through HCount. Invalid indices or fields raise a script runtime error; they do not return fabricated values. Actions are recorded after they occur and are available to every TRP, independent of the player's Keep log setting.

History includes human and computer players, including unsuccessful attacks. Each attack event represents one dice exchange, not an entire battle. No private card identities, TRP buffers or internal reasoning are exposed. Declining to attack or move does not produce an action.

Action kinds

Kind constantValueMeaning
AK_ASSIGNMENT1Initial territory claim, including random assignment; armies = 1.
AK_PLACEMENT2Initial or later placement; armies = actual number placed.
AK_ATTACK3Dice exchange; casualties and capture flag describe the outcome. Armies = mandatory occupation move on capture, otherwise 0.
AK_OCCUPATION4Additional movement into a conquered territory, including human auto-move; armies = number moved.
AK_FORTIFICATION5Friendly troop movement; armies = number moved.
AK_TURN_START6Beginning of a regular playing turn, before reinforcement and trades.
AK_TURN_END7End of a regular playing turn.
AK_REINFORCEMENT8Territory and continent income; armies = armies granted, excluding trades.
AK_CARD_TRADE9Completed card trade; armies = armies granted. Card identities are omitted.
AK_ELIMINATION10Player eliminated; player = attacker, opponent = eliminated player.
AK_GAME_END11Player = winner, or 0 if unfinished. Armies holds the termination status: 1 complete, 2 error, 3 turn limit, 4 time limit, 5 aborted.

Fields

All fields are integers. Unused fields are 0. Player and territory numbers match the existing API. Territory army snapshots are taken immediately before and after the action, not at the next TRP turn.

Incremental observation

Keep a cursor in an otherwise unused buffer, so each action is processed once. This example belongs inside a TRP procedure; declare I and LastSeen as integers. Reserve buffer 500 for the cursor.

LastSeen := Trunc(UBufferGet(500));
for I := LastSeen + 1 to HCount do begin
  if (HGet(I, AF_KIND) = AK_ATTACK) and
     (HGet(I, AF_OPPONENT) = PMe) then begin
    { Update an opponent model using HGet(I, AF_PLAYER) and the casualties. }
  end;
end;
UBufferSet(500, HCount);

History is retained in memory for the whole game without truncation, and resets for a new game. Large games use proportionally more memory. New saved games preserve actions and buffer cursors together. Older saved games have no earlier history, so observation starts when they are loaded. TRComp's synthetic test contexts have no history (HCount = 0). History access does not provide persistent cross-game opponent profiles.

Logging

In TurboRisk's Log window, use Log actions... to save the current history and stream future actions; Stop action log closes the file. Closing the window does not stop logging. Logging continues across new games until stopped or the application exits.

In TRSim, enter an optional Action log filename; leave it blank to disable. In TRSimCLI, use --action-log actions.jsonl. These files are separate from history.txt, .sgl and .scl, whose formats remain unchanged. Existing compatible action logs are appended, not overwritten. Invalid files and write failures are reported as errors.

Each UTF-8 JSONL segment begins with a game record containing format = "TurboRisk.actions", version = 1, type = "game", game and segment IDs, parent_game, history_from_start, and metadata (roster, engine version, map, assignment and card-value modes, and movement/trade flags). Roster entries contain id, name, human and program. Action records contain type = "action", game, segment, sequence (1-based), and all numeric fields listed above.

Enabling logging midgame includes all available earlier actions. Restarting logging creates a new segment and may repeat the same game/sequence pairs; use those pairs to deduplicate observations across segments. Restoring a save creates a new game ID with parent_game referencing the saved game, then emits its available history. An older save is marked history_from_start = false. Use separate files for concurrent processes. Logging records observations, not a replay of private state or a trained model.
