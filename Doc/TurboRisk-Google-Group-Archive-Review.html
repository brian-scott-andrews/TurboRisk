TurboRisk Google Group Archive Review

Completed October 26, 2026 | Source: Google Groups, turborisk

Coverage: I inspected all 30 discussion topics exposed by the group's public index and all-date search, spanning August 2010 through October 2024. I opened each topic and reviewed the message bodies made available on its thread page, including the multi-message discussions. The index's page=2 view repeated the same list rather than exposing additional topics.

This is an exhaustive review of the publicly exposed index as accessed on the date above, not a claim about private or removed group content. Deleted messages, inaccessible content, binary attachments, and external destinations linked from messages were not independently recoverable or inspected. The report summarizes rather than reproduces user posts; each topic links to its source thread.

Findings at a glance

The archive documents requests and discussion around multiplayer, broader/custom maps, alternate rules and visibility options, bot authoring, maps and TRP contributions, and defects encountered in game play or TRComp. Contributions and fixes are noted separately from suggestions: a feature being discussed is not evidence it was implemented.

Items with a verifiable repository counterpart include the Lazarus/Free Pascal port, community TRP files, the 2K map set, the fixed-aspect-ratio map, and the 2014 map update files. Corresponding map assets are present under maps; related player scripts are present under Players. Exact historical versions are not implied by matching names. TRComp execution-context regression tests were added and passed in this workspace, but that does not establish when or whether the original historical defect was fixed upstream.

Archive topics reviewed

  1. BUY DMT vapes and cartridges from southparkspychedelics (October 2024)

    Two visible messages are unrelated spam, not TurboRisk discussion.

  2. New map - original map with fixed aspect ratio (August 2021)

    A large-medium standard map variant with a fixed aspect ratio was shared; matching map files are present in this repository.

  3. Available Command List (January-February 2021)

    A user asked where to find the newer TRP command list and then found it in the help file.

  4. New map for TR (March 2019-April 2020)

    Garnett Williams shared simplified and Mercator-style 2K maps, including revisions; Brian Andrews said the package was added to GitHub. The repository contains the three named map variants.

  5. Port of TurboRisk to Lazarus/Free Pascal, now multiplatform (August-October 2019)

    The port was tested on Windows and Linux. Frank+ initially failed to load; a Windows program-selection bug, which also limited discovery to the first TRP, was reported fixed and confirmed by the thread participants. Executable size and build settings were also discussed.

  6. runaway game with all Vexers (December 2016)

    A long stalemate among three surviving Vexer bots produced armies above 100,000. A bot author described the situation as a deadlock arising from rational play and gaps in earlier AI versions.

  7. couple neat ideas (December 2016)

    Suggestions included allowing multiple adjacent army moves per turn and increasing the territory limit from 42 to 84, potentially enabling larger maps and more starting space for ten players.

  8. Announcing the release of TurboRisk source (March-July 2015)

    The GPL v3 source release and project collaboration were announced. Developer notes described code translation/refactoring, a Lazarus port, scalable vector maps, and identified multiplayer as the most-requested feature.

  9. Dominating12.com - My website for playing risk online (February 2012-December 2014)

    Nathan Scarbrough promoted an online multiplayer site with multiple maps, fog of war, capitals, live and asynchronous turns, and a live-game timer-refresh bug. The thread also mentioned two TurboRisk map updates and planned bot updates.

  10. Multiplayer? Is it even possible? (March 2011-December 2014)

    Players requested LAN/Internet multiplayer. Saved-game handoff was discussed as an awkward workaround because saving around card turn-ins was problematic. Mario called network multiplayer a major change and later described open sourcing as a way to enable community development.

  11. Defect in Projection Map - Iceland to Sweden bridge not shown (September 2013-December 2014)

    A missing visual bridge conflicted with the map's playable Sweden-Iceland connection. Nathan supplied map update files, and Brian confirmed updating his copy. The related update archive was previously hash-checked against repository map files.

  12. problem with static vs dynamic arrays (December 2010-December 2014)

    A TRP author reported trouble passing arrays into a routine and failures involving an unset territory result, then said the work had not continued. Follow-up testing retrieved the attached 8,650-byte brainless V.trp (not byte-identical to this repository's copy) and compiled it successfully in the historical TRComp 2.0.4 included with TurboRisk 2.0.5; its executable matches the user's supplied 2010 binary by SHA-256. The bot's TArray = array {[1..42]} of integer has its bounds inside a Pascal comment, so it is dynamic, as are the caller's arrays allocated with SetArrayLength; this attachment does not demonstrate a static-array parameter failure. It does contain separate likely defects: an inclusive 0..Length(DTArray) scan, uninitialized bFound/DT, no zero-node guard before indexing aNode[iNode], and PL/EA output values passed by value. A separate historical routine-runner probe confirmed matching fixed-array var and by-value parameter passing at runtime (return value 60); changing the bot's formal type to fixed-size while retaining its dynamic-array caller fails to compile. In a deterministic ConquerArea probe with a 42-element dynamic array and owned path 5-6-7, the inclusive loop left a sentinel return value of 99, while changing only the loop to 0..Length(DTArray)-1 completed with return value 2. The probe initialized DT/bFound and guarded the unrelated empty-node index so the scan bound was isolated; TRComp showed no explicit runtime diagnostic, so the result is differential evidence of the out-of-range read rather than a captured error message. A full TRSim game reproduced an invalid attack target 0 at turn 45 in brainless vi. Unlike brainless V and brainless_iv, which start with no attack source and only keep one when a target is selected, the failing vi callback exposed a nonzero source with no target after a capture. Refactoring vi to use a local candidate source and assign the output source only when a target exists fixed the same-seed run: the game completed in 46 turns without a TRP error. The requested Players/brainless vi.trp copy also retains the corrected dynamic-array scan bound and compiles in historical TRComp.

  13. bug concerning execution context (November 2010-December 2014)

    TRComp routine testing reportedly required clearing output and re-entering all arguments between runs; a wrapper around TWeakestPath could produce an access error. The thread confirms the reports but not a historical resolution.

  14. TurboRisk and TRSim Log Files Suggestion (December 2014)

    Brian Andrews asked whether TRSim and game-history log formats could be made compatible to avoid manual column editing. No implementation confirmation appears in the inspected thread.

  15. Ported AI's (December 2014)

    A batch of ported bots was shared. The author noted compile failures in two scripts, a territory-0 placement problem, missing bot/goal announcements that could stall games, and mixed performance among the bots. Corresponding player names exist in this repository, but that alone does not prove byte-for-byte version identity.

  16. A couple of new AIs (January-November 2014)

    Basic and Tectonic were shared. Brian later reported Tectonic sometimes aborted while placing to an invalid territory. Both scripts are present in this repository.

  17. Porting Old 1.2 TRPs (October 2012-November 2014)

    The discussion concerns porting older player scripts, double-precision variables, and placement/attack behavior. The visible code post includes a guard for avoiding a no-attackable-target loop; the report does not treat that code as proof every ported bot was fixed.

  18. Any way to show dice rolls? (June 2012-November 2013)

    A player suspected biased rolls and asked to see dice outcomes. A reply pointed to attacker/defender rolls in the status bar; later replies explained randomness and disputed perceived bias.

  19. History > Ranking > Points (April 2013)

    A user asked how ranking points worked because the help file was blank. Mario replied with the ranking, average-points, and head-to-head comparison rules.

  20. Risk Game (November-December 2011)

    A participant introduced a separate C# game with a gold bonus territory and asked for feedback. The exchange clarified its rules, wording, and lack of LAN/Internet multiplayer at that time.

  21. Change Computer vs. Human (July 2011)

    A user asked whether a player could be switched between human and computer after a game began. The response said there was no official way and that editing INI files might break the game.

  22. Copyright Infringement Problem Help (May 2011)

    Community members discussed possible naming and map changes after the trademark dispute. Suggestions included alternate territories and naval regions; Mario later outlined possible future multiplayer, hints, game-history playback, and sounds, without promising delivery.

  23. Infringement of Hasbro, Inc.'s RISK trademarks and copyrights (October 2010-January 2011)

    This long thread covers the legal letter, possible name/map changes, proposed alternate rules, map topology and territory ideas, and community suggestions. Mario reported changing the name to TurboRSC; the participants also discussed extra maps and preserving existing bot compatibility. Legal claims in the thread are historical statements by participants, not legal conclusions in this report.

  24. Stupid Question (January 2011)

    A player asked how cards are earned. Replies explained the one-card-per-turn conquest rule and cards received when eliminating another player.

  25. suggestion about player recognition (November 2010)

    Participants debated options for disabling AI recognition of human/AI identities or making play fully blind. Arguments addressed fairness, strategic play, AI quality, and possible API behavior; no implementation is confirmed by this thread.

  26. Player programming (November 2010)

    A new author asked which language and API to use. The reply directed them to the custom-TRP and API help, Pascal examples, TRComp, and sample scripts.

  27. Bug (October 2010)

    A user could not select certain player colors. Replies explained black and white were reserved for army-count text, suggested resetting the INI file, and the user reported reinstalling resolved the broader color-list behavior.

  28. Re: Infringement of Hasbro, Inc.'s RISK trademarks and copyrights (October 2010)

    A reply to the trademark discussion proposed alternate names and questioned the requested changes. It contains quoted portions of the legal discussion, not a separate feature request.

  29. Maps (August-September 2010)

    Vexer offered satellite or elliptical map versions at custom dimensions; a 1024x768 map was requested and Vexer said one was being made.

  30. TurboRisk AI (August 2010)

    Vexer offered help with custom-player development and invited suggestions to strengthen the Vexer bot.

Interpretation and verification boundaries

The archive contains both requests and shipped/community contributions. Examples of concrete contributions include the AI scripts, map packages, the open-source release, and the Lazarus port. Other ideas—including online multiplayer in TurboRisk itself, blind play, expanded territory counts, and log compatibility—should remain labeled as proposals unless independently verified in the code or release history.

Repository presence was checked only for the named map assets, player-script families, and the TRComp regression-test work summarized above. This document is an archive survey, not a full source-code audit of whether every historical request or defect is present in the current program.

Inspection was based on publicly accessible Google Groups pages retrieved on October 26, 2026. The group index and all-date search displayed the same 30 topics; unavailable/deleted material and attachment binaries are outside the stated coverage.
